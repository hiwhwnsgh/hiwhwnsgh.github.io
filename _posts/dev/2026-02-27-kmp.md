## 들어가며

KMP(Kotlin Multiplatform) 프로젝트에서 네이버 지도를 사용하려면 Android와 iOS 각각의 네이티브 SDK를 별도로 래핑해야 함. 기존에는 이를 위한 KMP 전용 라이브러리가 없었기 때문에 플랫폼별로 중복 코드를 작성하거나, `expect`/`actual` 보일러플레이트를 직접 구현해야 했음.

**Naver Map Compose**는 이 문제를 해결하기 위해 만든 라이브러리임. Jetpack Compose Multiplatform의 선언적 UI 모델 위에서 네이버 지도 SDK를 통합하여, 하나의 Composable API로 Android/iOS 양쪽 지도를 제어할 수 있음.

- **GitHub**: [ComposeNaverMap](https://github.com/hiwhwnsgh/kmp-naver-map)
- **Maven**: `io.github.hiwhwnsgh:naver-map-compose:0.0.3`

---

## 왜 직접 만들었는가

Google Maps의 경우 [maps-compose](https://github.com/googlemaps/android-maps-compose)가 공식적으로 존재하지만, 네이버 지도에는 KMP를 지원하는 Compose 래퍼가 없었음. 기존 선택지와 한계는 다음과 같음:

| 선택지 | 한계 |
|--------|------|
| 네이버 지도 Android SDK 직접 사용 | iOS 미지원, Compose 미지원 (View 기반) |
| [naver-map-compose (fornewid)](https://github.com/fornewid/naver-map-compose) | Android 전용, KMP 미지원 |
| expect/actual로 직접 래핑 | 프로젝트마다 반복 작업, 유지보수 비용 높음 |

결국 KMP + Compose Multiplatform 환경에서 네이버 지도를 선언적으로 사용할 수 있는 라이브러리가 필요했고, 직접 만들게 됨.

## 아키텍처

### 전체 구조

```
commonMain/          ← 공통 Composable API (NaverMap, Marker, Path 등)
├── NaverMap.kt
├── Marker.kt
├── PathOverlay.kt
├── CameraPosition.kt
└── ...

androidMain/         ← Android 네이버 지도 SDK 바인딩
├── NaverMap.android.kt
├── Marker.android.kt
└── ...

iosMain/             ← iOS NMFMapView 바인딩 (Kotlin/Native interop)
├── NaverMap.ios.kt
├── Marker.ios.kt
└── ...
```

### expect/actual 패턴

핵심은 `commonMain`에서 Composable 인터페이스를 `expect`로 선언하고, 각 플랫폼에서 네이티브 SDK를 `actual`로 연결하는 구조임.

```kotlin
// commonMain
@Composable
expect fun NaverMap(
    modifier: Modifier,
    state: NaverMapState,
    content: @Composable () -> Unit
)
```

```kotlin
// androidMain - Android 네이버 지도 SDK의 MapView를 AndroidView로 래핑
@Composable
actual fun NaverMap(
    modifier: Modifier,
    state: NaverMapState,
    content: @Composable () -> Unit
) {
    // AndroidView + NaverMap SDK 바인딩
}
```

```kotlin
// iosMain - NMFMapView를 UIKitView로 래핑
@Composable
actual fun NaverMap(
    modifier: Modifier,
    state: NaverMapState,
    content: @Composable () -> Unit
) {
    // UIKitView + NMFMapView 바인딩
}
```

이 구조 덕분에 앱 개발자는 `commonMain`의 API만 사용하면 되고, 플랫폼별 분기를 신경 쓸 필요가 없음.

## 설치 및 초기 설정

### 1. 의존성 추가

```kotlin
// build.gradle.kts (commonMain)
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("io.github.hiwhwnsgh:naver-map-compose:0.0.3")
        }
    }
}
```

### 2. Android 설정

네이버 지도 SDK의 클라이언트 ID가 필요함.

```xml
<!-- AndroidManifest.xml -->
<manifest>
    <application>
        <meta-data
            android:name="com.naver.maps.map.CLIENT_ID"
            android:value="YOUR_CLIENT_ID" />
    </application>
</manifest>
```

### 3. iOS 설정

iOS는 CocoaPods 또는 SPM을 통해 네이버 지도 SDK를 별도로 추가해야 함.

```ruby
# Podfile
pod 'NMapsMap', '~> 3.x.x'
```

`AppDelegate` 또는 앱 진입점에서 클라이언트 ID를 설정함:

```swift
// AppDelegate.swift
import NMapsMap

func application(_ application: UIApplication,
                 didFinishLaunchingWithOptions launchOptions: ...) -> Bool {
    NMFAuthManager.shared().clientId = "YOUR_CLIENT_ID"
    return true
}
```

## 주요 특징

- **Kotlin Multiplatform 지원**: 하나의 코드로 Android/iOS 네이버 지도 구현
- **Compose 전용 API**: `NaverMap`, `Marker`, `Polyline` 등 Composable 컴포넌트 제공
- **다양한 오버레이**: 마커, 경로선, 화살표 경로선, 정보 창, 원형 오버레이
- **고급 제어**: 카메라 위치, 위치 추적 모드, 지도 컨트롤 커스터마이징

## 사용 예시

### 기본 지도 + 마커

```kotlin
@Composable
fun MapSample() {
    val seoulCityHall = LatLng(37.5666102, 126.9783881)

    val mapState = rememberNaverMapState(
        initialPosition = CameraPosition(target = seoulCityHall, zoom = 12.0)
    )

    NaverMap(
        modifier = Modifier.fillMaxSize(),
        state = mapState
    ) {
        Marker(
            position = LatLng(37.5666, 126.9783),
            caption = "서울시청",
            iconTintColor = Color.Red.toArgb()
        )
    }
}
```

### 경로선 (Path Overlay)

두 지점 사이의 경로를 표현할 때 사용함.

```kotlin
@Composable
fun PathSample() {
    val mapState = rememberNaverMapState(
        initialPosition = CameraPosition(
            target = LatLng(37.5666, 126.9783),
            zoom = 13.0
        )
    )

    NaverMap(
        modifier = Modifier.fillMaxSize(),
        state = mapState
    ) {
        PathOverlay(
            coords = listOf(
                LatLng(37.5666, 126.9783),  // 서울시청
                LatLng(37.5512, 126.9882),  // 남산타워 방면
                LatLng(37.5443, 126.9861),  // 이태원 방면
            ),
            width = 10,
            color = Color.Blue.toArgb(),
            outlineColor = Color.White.toArgb(),
            outlineWidth = 2
        )
    }
}
```

### 화살표 경로선 (Arrowhead Path Overlay)

방향성이 있는 경로를 표현할 때 사용함. 내비게이션 안내 등에 적합함.

```kotlin
@Composable
fun ArrowPathSample() {
    NaverMap(
        modifier = Modifier.fillMaxSize(),
        state = rememberNaverMapState(...)
    ) {
        ArrowheadPathOverlay(
            coords = listOf(
                LatLng(37.568, 126.976),
                LatLng(37.570, 126.982),
                LatLng(37.565, 126.989),
            ),
            width = 20,
            color = Color.Green.toArgb()
        )
    }
}
```

### 정보 창 (Info Window)

마커를 탭했을 때 추가 정보를 보여주는 패턴임.

```kotlin
@Composable
fun InfoWindowSample() {
    val markerPosition = LatLng(37.5666, 126.9783)
    var showInfoWindow by remember { mutableStateOf(false) }

    NaverMap(
        modifier = Modifier.fillMaxSize(),
        state = rememberNaverMapState(
            initialPosition = CameraPosition(target = markerPosition, zoom = 15.0)
        )
    ) {
        Marker(
            position = markerPosition,
            caption = "서울시청",
            onClick = {
                showInfoWindow = !showInfoWindow
            }
        )

        if (showInfoWindow) {
            InfoWindow(
                position = markerPosition,
                content = "서울특별시청\n서울특별시 중구 세종대로 110"
            )
        }
    }
}
```

### 카메라 제어

프로그래밍 방식으로 카메라를 이동하는 예시임.

```kotlin
@Composable
fun CameraControlSample() {
    val mapState = rememberNaverMapState(
        initialPosition = CameraPosition(
            target = LatLng(37.5666, 126.9783),
            zoom = 12.0
        )
    )
    val coroutineScope = rememberCoroutineScope()

    Column {
        NaverMap(
            modifier = Modifier.weight(1f),
            state = mapState
        ) {}

        Row(
            modifier = Modifier.fillMaxWidth(),
            horizontalArrangement = Arrangement.SpaceEvenly
        ) {
            Button(onClick = {
                coroutineScope.launch {
                    mapState.animate(
                        CameraUpdate.scrollTo(LatLng(37.5666, 126.9783)) // 서울시청
                    )
                }
            }) { Text("서울시청") }

            Button(onClick = {
                coroutineScope.launch {
                    mapState.animate(
                        CameraUpdate.scrollTo(LatLng(35.1796, 129.0756)) // 해운대
                    )
                }
            }) { Text("해운대") }
        }
    }
}
```

## 고급 마커 기능

네이버 지도 SDK의 마커 옵션들을 Compose 파라미터로 그대로 노출함.

```kotlin
Marker(
    position = LatLng(37.5666, 126.9783),
    caption = "서울시청",
    captionTextSize = 14f,
    
    // 줌 제약: 줌 레벨 10~16에서만 표시
    minZoom = 10,
    maxZoom = 16,
    
    // 원근감: 지도 틸트 시 마커가 입체적으로 눕는 효과
    isPerspectiveEnabled = true,
    
    // Z-Index: 지도 심볼(건물명 등)보다 아래에 배치
    globalZIndex = -1,
    
    // 투명도
    alpha = 0.8f,
    
    // 아이콘 색상
    iconTintColor = Color.Red.toArgb()
)
```

| 파라미터 | 설명 |
|----------|------|
| `minZoom` / `maxZoom` | 마커가 표시되는 줌 레벨 범위 |
| `isPerspectiveEnabled` | 틸트 시 원근감 적용 여부 |
| `globalZIndex` | 지도 심볼 대비 마커의 렌더링 순서 |
| `alpha` | 마커 투명도 (0.0 ~ 1.0) |
| `iconTintColor` | 기본 마커 아이콘에 색상 오버레이 |

## 원형 오버레이 (Circle Overlay)

특정 반경을 시각적으로 표현할 때 사용함. 배달 가능 영역, 검색 반경 등에 활용 가능함.

    center = LatLng(37.5666, 126.9783),

    color = Color(0x220000FF),        // 반투명 파랑

## 주의사항 및 트러블슈팅

### 네이버 클라우드 플랫폼 앱 등록

네이버 지도를 사용하려면 [네이버 클라우드 플랫폼](https://console.ncloud.com/)에서 앱을 등록하고 클라이언트 ID를 발급받아야 함. Android는 패키지명 + SHA-1 핑거프린트, iOS는 번들 ID를 등록해야 함.

### iOS 빌드 시 NMapsMap 프레임워크 누락

CocoaPods으로 `NMapsMap`을 설치했음에도 빌드 에러가 발생하면, Xcode에서 **Build Settings > Framework Search Paths**에 `$(inherited)` 및 Pods 경로가 포함되어 있는지 확인할 것.

### Compose Multiplatform 버전 호환

라이브러리가 특정 Compose Multiplatform 버전에 의존하므로, 프로젝트의 Compose 버전과 호환되는지 확인이 필요함. 버전 충돌 시 `build.gradle.kts`에서 명시적으로 버전을 정렬할 것.

### ProGuard / R8 (Android)

릴리즈 빌드 시 네이버 지도 SDK 관련 클래스가 난독화되면 런타임 크래시가 발생할 수 있음. 네이버 지도 SDK의 ProGuard 규칙을 추가해야 함:

```proguard
-keep class com.naver.maps.** { *; }
-dontwarn com.naver.maps.**
```

### 메모리 관리

지도에 수백 개 이상의 마커를 동시에 표시하면 성능 저하가 발생할 수 있음. 대량 마커가 필요한 경우 클러스터링 처리를 고려할 것.
